== 인증

=== 회원가입

이메일로 가입해요. 토큰 없이 호출하며, 성공하면 `201 Created`와 `Location: /api/members/me`를 돌려줘요.
이미 가입된 이메일(대소문자·앞뒤 공백 차이는 무시)이면 `409 DUPLICATE_EMAIL`, 입력 규칙에 맞지 않으면 `400 INVALID_INPUT`이에요.

=== 로그인

이메일과 비밀번호로 로그인해요. 토큰 없이 호출하며, 성공하면 `200 OK`와 access token을 본문에 담아 돌려주고,
refresh token은 `Set-Cookie`로 내려줘요. 쿠키는 `HttpOnly`, `Path=/api/auth`이고 14일 동안 유효해요.
`Secure`와 `SameSite`는 서버 설정을 따라요(기본 `Secure`, `SameSite=Lax`).
이메일이 없거나 탈퇴한 회원이거나 비밀번호가 틀리면 모두 같은 `401 INVALID_CREDENTIALS`예요. 계정 존재 여부는 알려주지 않아요.

=== 토큰 재발급

로그인 때 받은 refresh token 쿠키로 새 access token을 받아요. 토큰 없이 호출하고, `Authorization` 헤더는 보지 않아요(만료된 access token이 붙어 있어도 돼요).
성공하면 `200 OK`와 새 access token을 돌려주고, refresh token은 새 값으로 회전해서 `Set-Cookie`로 내려줘요. 이전 토큰은 한 번 쓰면 끝이에요.
이미 쓴 토큰을 다시 보내면 탈취로 보고 그 로그인(패밀리)의 토큰을 모두 폐기해요. 다른 기기에서 한 로그인에는 영향이 없어요.
쿠키가 없거나, 모르는·만료된·폐기된 토큰이거나, 탈퇴한 회원이면 모두 `401 INVALID_REFRESH_TOKEN`이고 쿠키를 지우는 `Set-Cookie`(`Max-Age=0`)가 함께 내려와요.

=== 로그아웃

쿠키의 refresh token이 속한 로그인(패밀리)을 폐기해요. 쿠키가 없거나 잘못된 토큰이어도 항상 `204 No Content`이고, 쿠키를 지우는 `Set-Cookie`(`Max-Age=0`)를 내려줘요.
이미 발급된 access token은 만료될 때까지 유효해요.
