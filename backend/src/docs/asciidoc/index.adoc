=== 로그인

이메일과 비밀번호로 로그인한다. 토큰 없이 호출하며, 성공하면 `200 OK`와 access token을 본문에 담아 돌려주고,
refresh token은 `Set-Cookie`로 내려준다. 쿠키는 `HttpOnly`, `Path=/api/auth`이고 14일 동안 유효하다.
`Secure`와 `SameSite`는 서버 설정을 따른다(기본 `Secure`, `SameSite=Lax`).
이메일이 없거나 탈퇴한 회원이거나 비밀번호가 틀리면 모두 같은 `401 INVALID_CREDENTIALS`다. 계정 존재 여부는 알려주지 않는다.

=== 토큰 재발급

로그인 때 받은 refresh token 쿠키로 새 access token을 받는다. 토큰 없이 호출하고, `Authorization` 헤더는 보지 않는다(만료된 access token이 붙어 있어도 된다).
성공하면 `200 OK`와 새 access token을 돌려주고, refresh token은 새 값으로 회전해서 `Set-Cookie`로 내려준다. 이전 토큰은 한 번 쓰면 끝이다.
이미 쓴 토큰을 다시 보내면 탈취로 보고 그 로그인(패밀리)의 토큰을 모두 폐기한다. 다른 기기에서 한 로그인에는 영향이 없다.
쿠키가 없거나, 모르는·만료된·폐기된 토큰이거나, 탈퇴한 회원이면 모두 `401 INVALID_REFRESH_TOKEN`이고 쿠키를 지우는 `Set-Cookie`(`Max-Age=0`)가 함께 내려온다.

== 회원

이 장의 API는 모두 로그인이 필요하다. 요청마다 `Authorization: Bearer <access token>` 헤더를 보내야 하고, 없거나 유효하지 않으면 `401 UNAUTHORIZED`다.

== 배송지

이 장의 API는 모두 로그인이 필요하다. 요청마다 `Authorization: Bearer <access token>` 헤더를 보내야 하고, 없거나 유효하지 않으면 `401 UNAUTHORIZED`다.
배송지는 회원당 최대 10개까지 등록할 수 있고, 휴대폰 번호는 회원과 같은 규칙으로 검증해 숫자만 남겨 저장한다.
다른 회원의 배송지 ID로 수정·삭제하면 `404 ADDRESS_NOT_FOUND`다.

기본 배송지 규칙은 아래와 같다. 배송지가 1개 이상이면 기본 배송지는 항상 정확히 1개다.

* 첫 배송지는 `isDefault` 값과 상관없이 기본 배송지가 된다.
* `isDefault=true`로 등록하거나 수정하면 나머지 배송지는 기본이 해제된다.
* 수정에서 `isDefault=false`를 보내도 기본 배송지는 해제되지 않는다. 다른 배송지를 기본으로 지정해야 바뀐다.
* 기본 배송지를 삭제하면 남은 배송지 중 가장 먼저 만든 배송지가 기본이 된다.

=== 배송지 등록

성공하면 `201 Created`다. 이미 10개를 등록했다면 `400 ADDRESS_LIMIT_EXCEEDED`, 입력 규칙에 맞지 않으면 `400 INVALID_INPUT`(우편번호는 숫자 5자리)이다.

=== 상품 상세

판매 중(`ON_SALE`)인 상품만 보인다. 없거나 판매 중지·삭제된 상품이면 `404 PRODUCT_NOT_FOUND`다.
재고 수량은 내려주지 않고 품절 여부(`soldOut`)만 알린다. 옵션이 모두 품절이면 상품도 품절이다.
`categoryPath`는 루트부터 상품 카테고리까지의 경로이고, 옵션 정가(`price`)는 상품 정가에 추가금액을 더한 값이다.
기간 한정 세일이 진행 중이면 `saleRate`에 할인율이 담기고, 옵션 판매가(`salePrice`)는 옵션 정가에 할인율을 적용해 10원 단위 미만을 내린 값이다.
진행 중인 세일이 없으면(세일을 걸지 않았거나 기간이 아직 오지 않았거나 지났으면) `saleRate`는 `null`이고 `salePrice`는 `price`와 같다.

== 관리자 - 상품

이 장의 API는 관리자 전용이다. 요청마다 `Authorization: Bearer <access token>` 헤더를 보내야 하고, 없거나 유효하지 않으면 `401 UNAUTHORIZED`, 관리자가 아니면 `403 FORBIDDEN`이다.
상품은 옵션(SKU)과 이미지와 함께 한 번에 등록하며, 등록하면 `ON_SALE` 상태가 된다.

=== 상품 등록

성공하면 `201 Created`이고 `Location` 헤더에 상세 조회 URL이 담긴다. 입력 규칙에 맞지 않으면 `400 INVALID_INPUT`이다.
카테고리는 가장 아래 단계여야 하며, 아니면 `400 CATEGORY_NOT_LEAF`, 없으면 `404 CATEGORY_NOT_FOUND`다.
없는 브랜드면 `404 BRAND_NOT_FOUND`, 한 요청 안에서 옵션 이름이 겹치면 `409 DUPLICATE_SKU_NAME`이다.

=== 옵션 추가

성공하면 `201 Created`이고 옵션이 추가된 관리자 상세를 돌려준다. 새 옵션은 목록 마지막에 붙는다. 입력 규칙에 맞지 않으면 `400 INVALID_INPUT`이다.
상품당 옵션은 최대 20개이며 넘으면 `400 SKU_LIMIT_EXCEEDED`, 같은 상품에 같은 이름이 있으면 `409 DUPLICATE_SKU_NAME`이다.
없거나 삭제된 상품이면 `404 PRODUCT_NOT_FOUND`다.

=== 옵션 수정

성공하면 `200 OK`이고 수정된 관리자 상세를 돌려준다. 이름과 추가금액만 바꾸며 재고는 바뀌지 않는다. 재고는 재고 조정 API로만 바꾼다.
같은 상품의 다른 옵션과 이름이 겹치면 `409 DUPLICATE_SKU_NAME`이고, 자기 자신의 이름을 그대로 보내는 것은 괜찮다.
옵션이 없거나 다른 상품의 옵션이면 `404 SKU_NOT_FOUND`, 없거나 삭제된 상품이면 `404 PRODUCT_NOT_FOUND`다. 입력 규칙에 맞지 않으면 `400 INVALID_INPUT`이다.

=== 재고 조정

성공하면 `200 OK`이고 조정된 재고를 돌려준다. `delta`가 양수면 입고, 음수면 출고다. `delta`는 0이 아니어야 하고 절댓값이 100,000 이하여야 하며, 아니면 `400 INVALID_INPUT`이다.
결과 재고가 0보다 작아지면 `409 STOCK_NOT_ENOUGH`이고 재고는 바뀌지 않는다. 결과 재고가 100,000을 넘어도 `400 INVALID_INPUT`이다.
조건 검사와 갱신을 하나의 UPDATE 문으로 처리하므로 동시에 요청해도 재고가 음수가 되거나 갱신이 사라지지 않는다.
옵션이 없거나 다른 상품의 옵션이면 `404 SKU_NOT_FOUND`, 없거나 삭제된 상품이면 `404 PRODUCT_NOT_FOUND`다. 판매 중지(`STOPPED`) 상품의 재고는 조정할 수 있다.

=== 세일 설정

성공하면 `200 OK`이고 세일이 걸린 관리자 상세를 돌려준다. 이미 세일이 있으면 새 세일로 교체된다.
할인율(`rate`)은 1~90이고 시작·종료 시각(`startsAt`, `endsAt`)은 필수이며, 아니면 `400 INVALID_INPUT`이다.
종료 시각이 시작 시각보다 늦지 않으면 `400 INVALID_SALE_PERIOD`다. 없거나 삭제된 상품이면 `404 PRODUCT_NOT_FOUND`다.
시작 시각 정각부터 세일이 적용되고, 종료 시각 정각에는 적용되지 않는다. 응답의 `sale.active`는 지금 세일이 진행 중인지를 나타내며, 기간이 아닌 세일도 관리자에게는 보인다.
